What it checks

JWTs and JWKS

Algorithm confusion and alg: none. Header fields that ask the verifier to fetch a key from somewhere the token chose. Lifetimes measured in weeks. Millisecond timestamps that push expiry into the next millennium. Personal data riding in a payload that is base64, not encryption. Tokens that will not survive a header limit once one user accumulates enough groups. Symmetric keys published in a document meant to be public.

OpenID Connect and OAuth

Discovery documents advertising no PKCE, implicit flows nobody remembers enabling, and unsigned ID tokens. Authorization requests missing state or a challenge, with a wildcard redirect, or carrying a client secret through the browser. Trailing-slash issuer mismatches, which cost more debugging hours than any other single character in this field.

SAML

Whether the assertion is signed or only the response is, which is the difference between a working federation and signature wrapping. Multiple assertions and duplicate IDs. Missing audience restrictions, four-hour validity windows, SHA-1 digests, email addresses used as durable identifiers, and certificates that expire the weekend nobody is on call.

What it does not do

It does not verify signatures. That needs the key, and fetching keys means network calls, which would break the one promise this tool makes. Everything here is about what a token says and how it is put together, never about whether it is genuine. Verify in your own code, with the algorithm pinned, against a key set you fetched yourself.

Why it exists

Every tool of this kind is run by a vendor, on their servers, and people paste production tokens into them all day. authlint is one static file with no build-time dependencies and no runtime ones. Save it, open it on a machine with the network unplugged, and it works exactly the same. The source is on GitHub and it is short enough to read before you trust it. There is a full guide covering every input type, what each severity means, and how to use it during an incident.

The long version

If a finding here is the first time you have met the idea behind it, the Identity Dojo is the same material at length: OAuth and OIDC flows, SAML and web SSO, tokens and JOSE, and the attacks that made each of these checks necessary. Free, no accounts, same policy on tracking.
