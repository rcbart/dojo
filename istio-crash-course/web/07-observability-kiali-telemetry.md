# 7: Observability: Kiali & telemetry

*Because every request passes through a proxy, Istio can show you the whole system for free.
Concepts + a lab using the dashboards. ~20 min. Uses the add-ons from Setup Step 8.*

---

Istio gives you the classic **three pillars** of observability (metrics, traces, logs) plus a
live **service graph**, all generated by the proxies without instrumenting your apps. The add-ons
you installed (Prometheus, Grafana, Kiali, Jaeger) turn that data into dashboards.

## What each tool is for

| Tool | Shows you | Analogy |
|------|-----------|---------|
| **Prometheus** | Collects/stores the metrics the proxies emit | The database of numbers |
| **Grafana** | Graphs those metrics over time (dashboards) | The charts |
| **Kiali** | A live **map** of services and how they call each other | The X-ray of your mesh |
| **Jaeger** | **Distributed traces**: one request's whole path across services | The flight recorder |

## The golden signals, for free

Every sidecar emits standard metrics for the traffic it handles, so you get the **"golden signals"**
per service without any code:

- **Request rate** (traffic): requests/sec, e.g. `istio_requests_total`.
- **Errors**: the fraction returning 5xx.
- **Duration (latency)**: p50/p90/p99 response times, `istio_request_duration_milliseconds`.
- **Saturation**: connection/queue pressure.

These are consistent across every service in any language: the mesh measures at the proxy, so a
Go service and a Python service report identically.

## Distributed tracing (the one caveat)

A **trace** stitches together every hop a single request took (productpage → reviews → ratings),
with timing for each, so you can see *which* hop is slow. Istio's proxies generate and report the
spans automatically, **but** they can only link the hops if your apps **forward the tracing
headers** (like `traceparent`/`x-request-id`) from incoming to outgoing requests. That header
propagation is the one small thing apps must do; Bookinfo already does it. Everything else (span
creation, reporting to Jaeger) is the mesh.

## Lab: watch your traffic

Make sure the add-ons are installed (Setup Step 8) and generate steady traffic first:

```bash
# generate load for ~1 minute so the dashboards have data
for i in $(seq 1 200); do curl -s http://localhost:8080/productpage >/dev/null; sleep 0.3; done &
```

### Kiali: the service graph

```bash
istioctl dashboard kiali        # opens Kiali; go to the Graph view, namespace "default"
```

You'll see nodes for `productpage`, `reviews` (v1/v2/v3), `details`, `ratings`, with **arrows
showing live traffic**, request rates, and health colors. Padlock icons mark mTLS-encrypted edges.
Change the reviews split (Module 4) and watch the graph's arrows re-weight in real time. This single
view is why teams love Istio: you *see* your architecture and its health.

### Grafana: the metrics dashboards

```bash
istioctl dashboard grafana      # open the "Istio Service Dashboard"
```

Pick the `productpage` service and watch request volume, success rate, and latency percentiles:
the golden signals, graphed.

### Jaeger: a single request's path

```bash
istioctl dashboard jaeger       # search service "productpage", find a trace
```

Open a trace to see the waterfall: productpage's call fanning out to details/reviews/ratings, each
hop's duration. When something is slow, this tells you exactly *where*.

## Tuning what's collected (Telemetry API)

You control telemetry declaratively with the **Telemetry** resource: e.g. sample 100% of traces in
dev, add custom metric dimensions, or toggle access logging:

```yaml
apiVersion: telemetry.istio.io/v1
kind: Telemetry
metadata: { name: mesh-default, namespace: istio-system }
spec:
  tracing:
  - randomSamplingPercentage: 100      # trace everything (dev only; lower in prod)
  accessLogging:
  - providers: [ { name: envoy } ]     # turn on access logs
```

## Check yourself

1. Match tool to job: Prometheus, Grafana, Kiali, Jaeger. *(Prometheus stores metrics; Grafana
   graphs them; Kiali maps the services; Jaeger shows per-request traces.)*
2. Which golden signals do sidecars emit for free? *(Request rate, errors, and duration/latency,
   plus saturation.)*
3. What's the one thing your apps must do for distributed tracing to link hops? *(Forward the
   tracing headers from incoming to outgoing requests.)*
4. What does Kiali's graph show? *(A live map of services, their call edges, traffic rates, health,
   and mTLS status.)*
5. How do you turn trace sampling to 100%? *(A Telemetry resource with
   `randomSamplingPercentage: 100`.)*
